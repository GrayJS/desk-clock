# Morrow 桌面时钟

简体中文 | [English](README.en.md)

一款面向 Windows 11 的轻量桌面时钟与专注工具。使用 Tauri 2、React、TypeScript 和 Three.js 构建，不依赖 Electron。

当前稳定版本：[`v0.6.13`](https://github.com/GrayJS/desk-clock/releases/latest)

v0.6.13 将记录页升级为日、周、月、年报表，支持月历点选日报，并提供更紧凑的响应式布局。
查看 [本次发布说明](docs/releases/v0.6.13.md) 或 [完整更新记录](CHANGELOG.md)。

## 下载与安装

1. 打开 [GitHub Releases](https://github.com/GrayJS/desk-clock/releases/latest)。
2. 下载 Windows x64 安装包：[v0.6.13 安装程序](https://github.com/GrayJS/desk-clock/releases/download/v0.6.13/Morrow._0.6.13_x64-setup.exe)。
3. 运行安装包并启动 Morrow。

需要 Windows 10/11 x64 与 Microsoft Edge WebView2。Windows 11 通常已经预装 WebView2。

已安装旧版的用户可打开“设置 → 手动检查更新”，确认后静默升级，原有本地记录与设置会保留。

## 主要功能

- 实时时钟与日期，窗口默认置顶
- 迷你、标准、展开三种窗口尺寸，支持标题栏快速切换、自由缩放和拖动
- 迷你模式保留模式切换、倒计时、开始/暂停、重置和进度显示
- Windows 托盘图标支持分别配置单击和双击动作，可上传 PNG、JPG 或 WebP 自定义图标
- 深色、浅色与跟随 Windows 系统三种主题模式
- 简体中文与 English 即时切换
- 统一设置面板，集中管理外观、窗口、启动与更新选项
- 普通计时器提供专注和休息两种模式；专注完成后停留在专注模式，等待手动开始下一轮
- 常用时长快捷档位与 1–180 分钟自定义倒计时
- 第三个“循环”标签页支持设置 1–99 轮及独立的专注、休息时长，按计划自动衔接
- 本轮目标、随手记及已完成或跳过的计时记录，清空记录前需二次确认
- 最小化或关闭后驻留系统托盘，可从托盘恢复或退出
- 可选开机自启动，并与 Windows 实际启动项状态同步
- 按截止时间计算倒计时，可通过原生后台任务在完成时发送 Windows 通知
- iOS 风格磨砂玻璃界面，配合立体数字、按钮高光和按压反馈；Windows 原生 Mica 材质与 Acrylic 回退

## 快速上手

标准与展开窗口中的标签页依次为：

1. **番茄钟**：设置当前专注或休息时长，填写本轮目标与随手记，然后开始计时。
2. **成长树**：查看当天专注产生的番茄，以及随成果逐步进化的树形。
3. **循环**：设置多轮专注与休息计划，并自动衔接每个阶段。
4. **记录**：按日、周、月、年查看专注报表；月报为日历，点击日期进入日报。展开计时明细可查看备注，清空前会要求确认。

普通专注计时完成后会记录本轮并停止；普通休息完成后切回专注模式，同样等待手动开始。
“完成本轮”会将专注按设置的整轮时长记为完成，并非按实际已经过的时间统计。

## 设置

点击标题栏齿轮按钮打开统一设置面板。面板中的修改会即时生效：

- **外观**：跟随系统、浅色或深色主题，以及简体中文或 English
- **窗口**：迷你、标准或展开尺寸，并可切换窗口置顶
- **Windows 托盘**：分别配置托盘图标的单击和双击动作，可选显示主界面、开始/暂停、重置、切换模式、置顶、打开设置或无操作；新安装默认单击显示主界面、双击打开设置
- **系统**：开机启动、Windows 计时完成通知和签名更新检查

窗口置顶和尺寸切换仍保留在标题栏作为高频快捷操作；尺寸按钮会按迷你、标准、
展开的顺序循环切换。开机启动读取并修改 Windows
实际启动项；在普通浏览器前端预览中该开关不可用。

自定义托盘图标支持 PNG、JPG、WebP，文件不超过 2 MB，导入后等比缩放并留边至 32×32。
托盘右键菜单提供“显示主窗口”和“退出 Morrow”；标题栏的最小化与关闭按钮都会将窗口隐藏到托盘。
升级时已有的托盘配置可能与新安装默认值不同，可在设置中查看或重新选择。

| 尺寸档位 | 窗口大小 | 适用场景 |
| --- | ---: | --- |
| 迷你 | 360×210 | 常驻桌面并直接操作计时器 |
| 标准 | 420×747 | 手机竖屏比例，日常计时与紧凑报表 |
| 展开 | 720×520 | 并排查看计时内容或完整成果树 |

上述尺寸以逻辑像素表示，实际屏幕像素数取决于 Windows 缩放比例。下次启动时会恢复保存的
尺寸档位，自由拖动调整后的精确宽高不会单独保存。标题栏尺寸按钮显示当前档位，
并在悬停提示中说明点击后将切换到的档位。

迷你窗口只显示时钟和简化计时控件，不显示四个标签页。配置新循环前请先切回标准或展开窗口；
已有循环运行时，可点击迷你模式中的“查看循环”回到标准窗口的循环页。

## 番茄循环

打开第三个“循环”标签页，设置轮数（1–99 轮）、专注时长和休息时长（各 1–180 分钟），
再点击“开始循环”。新安装的默认计划为 4 轮、专注 25 分钟、休息 5 分钟。
循环计划与普通计时器时长分别保存，修改一处不会同步修改另一处。

例如设置 **4 轮、每轮专注 25 分钟、休息 5 分钟**，实际会运行 4 次专注和 3 次休息，
预计总时长为 **115 分钟**，最后一次专注结束后停止。

- 按“专注 → 休息 → 下一轮专注”自动运行，最后一轮专注结束后直接停止，不追加休息
- 每次专注完成照常写入记录并为成果树增加番茄；休息不生成专注记录
- 支持暂停、继续和结束循环；运行中及暂停时固定计划，结束循环后可修改轮数与时长
- 普通计时器、迷你计时器与托盘的开始/暂停、重置操作控制同一个当前计时；重置仅重置当前阶段并暂停
- 在番茄钟页手动“完成本轮”也会推进循环；若当前已暂停，下一阶段仍保持暂停
- 循环页、普通计时器和迷你计时器均可跳过当前专注或休息；运行中跳过会继续下一阶段，暂停时跳过保持暂停
- 跳过会保存阶段类型、计划时长、实际用时、时间与备注，不会伪装为完成一轮；跳过最后一轮专注会直接结束循环
- 跳过的专注按实际用时计入今日专注时长，不增加已完成轮数或番茄；跳过休息不计入专注时长
- 循环中禁止从普通计时器切换模式或修改时长；迷你窗口可通过“查看循环”返回标准窗口的循环页
- 每段结束沿用 Windows 通知偏好；关闭到托盘后计时继续，结束循环保留已完成的专注记录，不记录未完成阶段

如果“开始循环”暂时不可用，请先暂停并重置普通计时器，或完成当前计时，再启动循环。

计时与循环需要 Morrow 进程保持运行。暂停只保留本次运行中的进度；退出应用后，剩余时间、
当前轮数和未完成的随手记不会恢复，但已保存的循环计划、专注记录和设置仍会保留。

## 每日番茄成果树

- Three.js 渲染低多边形动态成长树
- 当天每完成一轮专注，树上增加一颗番茄
- 树会随番茄数量改变树高、冠幅、分枝和叶片密度，并平滑过渡到下一形态
- 倒计时期间，下一颗番茄会从绿色小果逐渐长大并成熟变红
- 暂停时保留当前成熟度，重置或切换模式后取消本轮生长
- 番茄数量按本机保存的当天已完成专注记录计算，跳过记录不增加番茄；日期变化后从新的每日成果树开始，不会删除历史记录
- 为控制渲染开销，树上最多显示 50 颗番茄，计数仍按当天保存的记录数量显示
- 树体支持呼吸、摆动、鼠标视差和响应式缩放动画

| 当日番茄数 | 树的形态 |
| ---: | --- |
| 0–1 | 幼苗 |
| 2–4 | 幼树 |
| 5–9 | 成长 |
| 10–17 | 繁茂 |
| 18+ | 丰收 |

## 版本更新

- 启动应用后自动检查一次签名更新
- 后台每 1 小时检查一次新版本
- 设置面板提供手动检查更新按钮
- 发现新版本后先显示提示，由用户选择“立即更新”或“稍后提醒”
- 用户确认后在后台静默下载并安装，不会未经确认自动安装
- 自动更新失败时才打开手动下载入口
- 检查结果会反馈“已是最新版本”或网络错误状态
- 当前应用版本显示在底部状态栏

## 数据与隐私

- 专注记录、当前目标、时长、循环计划、主题、语言、窗口尺寸、置顶、通知和托盘偏好均保存在本机 `localStorage`
- 最多保存最近 200 条计时记录，包括已完成的专注及手动跳过的专注、休息；超过后自动移除最早的记录
- 每日汇总独立保存，旧明细超出 200 条后，月报和年报仍保留汇总；首次升级只能从仍存在的明细初始化，无法恢复旧版已移除的记录
- 今日时长为已完成专注的计划时长，加上跳过专注的实际用时，再按完整分钟显示；番茄数量仅统计已完成专注，统计基于每日汇总
- 随手记在专注完成或手动跳过阶段时随记录保存，其余未结束阶段的随手记仅在当前运行中保留
- 清空会同时删除全部计时明细与报表汇总，并同步影响今日统计与成果树；不会清除目标、循环计划或其他设置
- 开机启动由 Windows 登录启动项管理，不会上传到远程服务
- 不需要注册账号
- 不上传专注记录或随手记
- 应用不向服务端发送专注内容、随手记或配置；网络请求用于加载 Google Fonts 字体，以及通过 GitHub 检查和下载更新

## 本地开发

Windows 开发需要：

- Node.js 20+ 与 npm
- Rust stable，使用 MSVC 工具链
- Microsoft C++ Build Tools，安装“使用 C++ 的桌面开发”工作负载及 Windows SDK
- Microsoft Edge WebView2 Runtime

安装方法见 [Tauri Windows 开发依赖说明](https://v2.tauri.app/start/prerequisites/#windows)。
以下命令均在仓库根目录执行：

```powershell
npm ci
npm run tauri dev
```

仅运行前端预览（不提供原生托盘、窗口控制、开机启动、Windows 通知或静默更新）：

```powershell
npm run dev
```

### 测试与检查

在仓库根目录执行：

```powershell
npm test
npm run build
cargo test --locked --manifest-path src-tauri/Cargo.toml
```

`npm test` 验证循环阶段顺序、跳过与末轮结束、计划隔离、输入范围、实际用时和旧记录兼容；发布流水线会先运行这些测试，再构建安装包。

## 构建安装包

### 仅用于本机安装的构建

仓库默认启用了自动更新产物签名。若没有发布私钥，可在仓库外新建覆盖配置，
例如 `C:\morrow-build\local-build.json`，内容如下：

```json
{
  "bundle": {
    "createUpdaterArtifacts": false
  }
}
```

然后在仓库根目录运行：

```powershell
npm run tauri build -- --config C:\morrow-build\local-build.json
```

这样会生成供本机安装的 NSIS 安装包，但不生成用于分发自动更新的 `.sig`。
安装包输出目录为：

```text
src-tauri/target/release/bundle/nsis/
```

### 发布可自动更新的版本

正式发布保留 `createUpdaterArtifacts: true`，使用与应用内公钥匹配的私钥。
本地签名构建需在当前终端设置 `TAURI_SIGNING_PRIVATE_KEY` 和相应的
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`，再运行 `npm run tauri build`；仅在 `.env` 中填写无效。
配置方式见 [Tauri 更新签名说明](https://v2.tauri.app/plugin/updater/#signing-updates)。

统一 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`
中的应用版本及 `src-tauri/tauri.conf.json` 版本，再推送对应的 `v*` 标签。GitHub Actions 会先运行
循环逻辑测试，再构建 Release，上传安装包、自动更新校验签名 `.sig` 和清单 `latest.json`。
CI 从仓库 Secrets 读取上述签名凭据；私钥与备份应始终保存在仓库之外。
